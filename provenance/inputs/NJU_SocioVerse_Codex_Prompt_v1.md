## 1. 项目事实与研究目标

用户描述的现有项目：
- 以南京大学校园为场景，通过自然语言解析事件条件和观察时间。
- 从约 5000 个具有稳定人格、兴趣、经历及目标的合成人物中选取模拟群体。
- 人物依据自身状态、日程、实际收到的信息和任务内记忆，由 Jev 或 LLM 生成行为概率。
- 环境结算行动结果、资源约束和关系网络中的信息传播，再反馈给后续决策。
- 三维校园与报告展示群体变化、个人轨迹和推演依据。

已知不足：不同类型事件仍有部分独立执行路径；人物与关系主要是合成数据；人格的真实行为预测增益未充分验证；部分宏观结果依赖模型综合判断。

上述是用户陈述，不是你已经验证的代码事实。审计后逐项标为“有实现证据”“待运行验证”“未找到”，附具体路径。5000 个合成人物绝不能写成 5000 名真实受试者或已验证的学生数字分身。

新项目定位：可校准、可组合、可验证的社会模拟研究框架。
候选论文工作题目：From Local Decisions to Collective Outcomes: Calibrated Compositional Social Simulation。
比赛目标是优先交付完整、可靠的 Track C 研究作品；论文来自同一套方法与实验，不另起一个庞大的产品工程。

核心问题：能否利用真实过程证据校准跨事件共享的行为机制，使其在未见事件组合中，改善个体预测与群体轨迹？

候选方法主线：跨事件共享机制＋局部行为校准＋闭环轨迹约束＋独立组合泛化验证。
这是一项待证伪的假设，不是已成立的创新。不要承诺获奖、顶会录用或预设提升比例。

## 4. 新框架的运行契约

采用同一个内核承载不同事件；事件通过配置和机制组合表达，不在顶层继续堆“活动 A 专用引擎/活动 B 专用引擎”。

运行主线：
EventSpec → LocalObservation → DecisionProposal → ActionAttempt → Interaction / Settlement → StateUpdate → Trace → Metrics。

设计清楚的类型与校验，至少包含：
- EventSpec：时间轴、目标群体、初始知情者、资源、允许动作、外部事件、机制配置、评测目标。
- Persona：相对稳定特征，与动态状态分离。
- AgentState：日程、预算、目标、局部信念及真实经历的记忆。
- Observation：信息来源、发送/到达/查看时间、可见范围和证据 ID。
- DecisionProposal：动作候选、原始概率、校准概率、后端及版本。
- ActionAttempt / Outcome：尝试、成功/失败、资源变动与反馈原因。
- TransitionRecord：旧状态、观测、动作、结算、新状态、随机数键及证据引用。

要求：
1. 区分世界客观状态、个体可见信息和研究者全知视图；决策模块不能访问未来标签、其他人的秘密状态或未接收消息。
2. 发送、送达、查看、理解、采纳不是同一个状态；不可观察的心理变量标为估计，不伪造标签。
3. 不泄漏隐藏约束：学生不知道名额已满时可以尝试报名，由环境返回失败；不能用真实全局状态提前剔除他认为可行的动作。
4. 区分意图、尝试、成功和到场；资源分配、日程冲突和取消释放由可测试代码结算。
5. 定义同时行动的时间语义与公平冲突规则，避免循环顺序造成系统性优势。共享资源集中结算。
6. 明确每个概率对应的观察时间窗；改变步长不能无意增加重试机会。必要时采用风险率/等待时间模型，不把不同时间粒度的概率直接复用。
7. 反馈允许个体合理适应；不把“永远不变”当作真实性。
8. 宏观统计从日志计算。LLM 只组织文字解释，不再改写数值；推演依据来自执行证据，不是事后编造的心理解释。
9. 主实验使用人工审核、冻结的 EventSpec；自然语言解析单独评测，避免混淆解析错误与模拟错误。
10. 主实验不读取模拟外部的真实测试反馈；训练校准循环与运行时人物状态更新是两回事。

## 5. 先实现最小机制集与三个研究场景

优先复用并统一：信息接触/查看、参与选择、同伴分享、名额竞争、时间冲突、取消/候补、结果反馈。

场景 S1：信息通知与活动参与。
场景 S2：有限名额、等待与退出。
场景 S3：同伴传播＋两个活动时间冲突＋有限名额的组合场景。

同一内核和同一接口运行三个场景；将“机制是否出现”“组合是否出现”“事件是否出现”记录为可检查的配置。
S3 可作为预先保留的组合测试设计，不意味着已有真实验证数据。真实事件不足时只报告合成机制测试，不包装为真实泛化。

## 6. 方法实现：从低参数可解释方案开始

将 Jev/LLM 看作可替换的原始概率后端；实现 OfflineFixtureBackend、SimpleStatisticalBackend，以及经核验接口的 Jev/LLM 插件。
不将模型 confidence 当作真实人类概率已经校准的证据。

先实现阶段级、跨事件共享的校准器，优先使用低维参数：
- 二元阶段可采用原始 log-odds 的偏置与特征修正。
- 互斥多选采用联合 softmax 校准，不将独立二元概率错误拼接。
- 特征限定为事前可见的兴趣、历史、时间约束和已知同伴信息等。
- 可比较完全共享与正则化的分组偏差；共享规律不等于所有人物具有相同概率。
- 禁止为每个测试事件单独拟合参数、使用测试事件 ID 记忆答案或读取事后信息。
- 阶段监督只使用真实可观测标签；缺失不当成“未发生”。明确风险集、缺失/删失与选择性可观测的处理和限制。

建议训练路线：
A. 用训练集行为阶段监督拟合局部校准参数。
B. 比较仅局部监督、仅宏观轨迹监督、过程与轨迹共同约束。
C. 在训练事件的完整自主推演上优化少量共享参数，并保留局部拟合与正则化约束。
D. 用开发事件选择方案，冻结后评估独立事件与未见组合。

闭环目标可由阶段 NLL/Brier、可观测群体轨迹误差、正则项构成。指标归一化和权重必须记录。
不要声称“几个损失相加”就是新算法；真正的候选贡献应明确落在共享参数结构、过程证据利用与组合迁移上。
离散采样不能直接假定可微：先选可解释、低维的黑箱优化或其他适用方案；只有确认必要时才引入可微松弛/复杂优化，并记录引入的偏差。
使用配对随机流降低比较噪声，但共享随机数不是干预效应正确性的证据。

对于总量相似、过程相反的多种参数解，比较其新情境表现并报告不可辨识性；不能根据宏观拟合唯一恢复真实人格、动机或因果机制。

## 7. 可复现性与机制测试优先于界面

使用统一追加式事件日志，保存输入、配置、模型及提示词版本、有效依赖、数据切分、响应缓存引用、随机流和成本。
随机键至少含 run、agent、逻辑时间、机制和抽样用途，避免并发调度顺序改变所有结果。
明确区分：固定响应回放可复现，以及重新调用外部模型；固定 seed 不保证第三方 API 逐字重现。

至少测试：
- 未接收信息不出现在 Observation 中；测试未来标签不进入决策或训练。
- 容量/预算守恒、无负库存、重复报名约束、取消与候补结算。
- 日期和日程有效；时间步改变不会凭空增加独立尝试。
- 并发结算公平；Agent 遍历次序不会产生非预期偏差。
- 每个宏观数字可追溯到日志；分阶段总量在定义上相容。
- 固定输入与响应缓存可重建状态轨迹。
- 同一前缀分叉在干预前一致；不得沿用未来分支信息。
- 官方适配不会丢失原生微轮次轨迹，也不会重复推进时间、记忆或资源。
- 没有源代码写入、原库连接、真实通知、秘密输出或越界文件写入。

如果官方 study 面板不保存足够细的微事件，在新项目保存完整 sidecar 日志；核验接口和版本后选择映射方式，不能假设任意官方版本天然支持精确回放。

## 8. 科研实验与真实数据边界

至少设置以下可运行对照，按主问题控制规模：
B0：隔离的原系统冻结副本；不能运行时明确缺失。
B1：简单统计/离散选择模型。
B2：统一环境＋原始 Jev/LLM，无新增校准。
B3：共享机制＋仅局部阶段校准。
B4：共享机制＋仅宏观轨迹校准。
Ours：共享机制＋过程与闭环轨迹约束。

消融优先：去掉跨事件共享、去掉过程标签、去掉闭环约束；再做有数据支撑的画像与网络实验。借鉴 CALM 的实现应叫 CALM-inspired，不冒充完整官方复现。
至少比较两个有授权、预算允许的决策后端或模型规模，检验机制增益是否依赖某一后端；不盲目开展昂贵大矩阵。

评测模式分开：
1. One-step：给真实历史，预测下一步。
2. Free rollout：只给起点和事前已知外部安排，自主演化。
3. Held-out composition：冻结参数，在未见事件组合上测试。

数据切分以事件和时间为基础；同一活动的行级随机拆分不能证明跨事件泛化。分别报告同人新事件和新人新事件。画像、检索、提示词示例与参数拟合遵守同一切分边界。

预先锁定个体行为概率指标及群体时间轨迹指标，报告预测区间、校准图、阶段误差、约束违反率、失败案例与费用。统计分析以独立真实事件/合适群集为单位考虑相关性；模拟随机种子和同一次活动的参与者不是独立事件数量。

数据 provenance 至少分 synthetic、real_observed、model_generated、derived；补齐未知真实数据的接口和模板，不自动编造或假装取得数据。真实信息缺失不填假标签。
涉及真实学生时先提出最小采集、同意与审批方案。未经授权不得抓取、联系参与者或把可识别数据传给模型供应商；公共复现包不得包含身份、秘密或可再识别关系图。

没有真实数据时继续做工程验证和合成机制辨识测试，明确结果只支持这些范围。内部模拟反事实不等于真实因果效应；同一学生不可观测的个人反事实不作为已知标签。L1–L4 问卷可辅助个体模块，但不替代真实连续行为观测。

## 9. 比赛适配只能发生在新项目

先让原生研究内核运行，再按照当前 SocioVerse2 的实际版本建立薄适配层。核对 EnvironmentProvider、PopulationProvider、DecisionModel、MetricCollector 等真实接口，不照着名称猜构造器。

studies/nju_compositional_simulation/ 及所有适配代码只能建立于 RESEARCH_ROOT。依赖固定版本或提交；适配比较在“原始逻辑的隔离副本”和“其未加入新机制的包装版”之间进行。不要要求改进后的模型与旧模型结果相同。

研究模型版本、环境干预分支和不同随机重复是三种不同实验对象，要分别编号。改变模型算法不能伪装成只改变外部环境的因果干预。

不修改官方框架核心，不修改原项目；外部导入只指向新项目内的许可副本。确实需要兼容补丁时只在新项目 fork/vendor 中记录，且先验证是否有非侵入适配方案。

## 11. 首轮立即执行与验收

按以下顺序行动，不因没有真实数据而停在方案阶段：
A. 确认真实路径和权限，在原目录之外建立独立工作区；建立初始隔离清单。
B. 只读审计关键调用链，核实比赛规则与直接近邻，建立上述事实源和复用清单。
C. 复制最小必要模块，创建离线后端和一条原生统一执行链。
D. 用约 30 个明确合成人物、短时间窗口跑通 S1 与 S2，再运行 S3 组合 smoke test；这是软件验收，不是科研有效性结论。
E. 跑信息隔离、资源守恒、日志指标、确定性回放和原项目完整性测试。
F. 实现可替换校准接口、最简单训练/评测分离原型，以及正式实验配置；缺真实标签时只用单独标记的合成 fixture 检查计算与接口。
G. 在新项目形成参赛提案结构草案、真实数据接入模板、核心实验表和最新交接文件。
H. 官方适配与强基线按优先级继续推进；不以适配工作掩盖原生内核或数据尚未完成。

首轮交付必须明确：
- SOURCE_ROOT 与 RESEARCH_ROOT 的绝对路径。
- 原项目是否保持不变，核验了什么、没有核验什么。
- 复用了哪些原文件，新增了哪些独立模块。
- 可复制运行的命令、实际测试结果与输出路径。
- 当前哪些只证明工程正确性，哪些拥有真实数据证据。
- 比赛规则的核实状态，以及后续三项最重要任务。

禁止用“大规模重构”“换最新模型”“做全新前端”替代上述目标。也不要仅输出调研与规划后就宣称任务完成。

费用、真实数据访问、越界文件权限、公开发布和正式报名/提交需要另有明确授权；除此之外，按上述边界直接推进能完成的工作。保持原项目完整，独立完成参赛研究，不进行产品迁移或替换。
